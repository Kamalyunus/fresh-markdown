# The pricing folder

One command, the hourly price, and what it needs. This folder does not
import from, read from or write to anything outside itself. Put it on the
host, install the pinned libraries, and the cron line below runs from it.
It prices at the engine's optimal price, every hour, and nothing else: no
exploration, no learning, no model fitting, no feature building. Those run
in the owner's repository and their results arrive here as files.

The full handover — the loop, who does what, every field, every rejection
reason — is `docs/engineering_handover.html`, in this folder. This page is
the short version for the person setting the host up.

## The command

```
python3 price_hour.py --snapshot snapshots/<day>T<hh>.parquet \
    --features features/<day>.parquet --workers 0 \
    --out decisions/<day>T<hh>.csv --report reports/hours/<day>T<hh>.json
```

| In | Out |
| --- | --- |
| the shelf at the top of the hour in the feed's schema, with the `episode_id` you assign (`snapshots/`, parquet, CSV or JSONL) | one row per snapshot row: the discount to apply as a percent and as a price, or `rejected` with the reason (`decisions/`); the hour's counts (`reports/hours/`) |
| the day's feature table, `features/<day>.parquet` — the owner's morning run writes it and it is copied here (see *What arrives*) | one decision and one rejection stream in `events_store/`, append-only, locked on every write |

The command sets this folder as its working directory before it runs, so
call it from anywhere; a relative path in an argument is relative to this
folder. `--help` lists every flag; `--dry-run` prices against a scratch
copy of the store and commits nothing.

It exits 0 whenever it ran, even if every shelf came back `rejected`:
alert on the report's `rejected` count, not the exit code. It exits
non-zero only when it could not run at all — the console output says
which of the host, the config, the artifacts or the feature table is
missing or moved.

## What arrives, and from whom

Nothing in this folder generates an artifact. The owner's chain does, in
the repository, and copies the result in on every seal and every run of
their driver. `artifacts/synced.json` names the bundle and lists what
arrived and when. You never copy a file by hand; if the folder reaches
you without one, ask the owner for a sync.

| Folder | What | Who puts it there |
| --- | --- | --- |
| `artifacts/` | the five files the hour opens: the model, its feature schema, the level factors, the dispersion table, the posterior | the owner's sync |
| `features/` | `<day>.parquet`, the day's feature table the hour joins on; the owner's morning run builds it from yesterday's feed and the sync copies it here | the owner's sync, every morning |
| `config.yaml` | the owner's config pruned to the keys this command reads, generated by the sync; `data.launch_date` null refuses to price, which is the intended state until launch day | the owner's sync |
| `snapshots/` | the top-of-hour rows | you, hourly |
| `decisions/`, `reports/hours/` | the response and the hour's counts | the command |
| `events_store/` | the record of every priced and every refused shelf-hour. Back it up daily | the command |
| `logs/` | stdout, collected by the cron line | cron |
| `examples/`, `docs/` | the four example tables (the shape, the names and the units, nothing about production) and the handover page | the owner |
| `src/` | the engine: the hourly path's modules, one file per repository module. `MANIFEST.json` says which are verbatim copies and which this folder edits, and why | the owner |

The nightly feed and the failed-pushes table are yours to deliver as
before; they go to the owner's repository, where the morning lane reads
them, not to this folder. The owner runs the table checks there on the
files you send, including the check of this command's response against
its snapshot; send the first hour's snapshot and response for that.

## This phase: exploit only

This folder prices exploit-only, by construction (`EXPLOIT_ONLY` in
`src/ops/price_batch.py`). Every decision is the engine's optimal price
for the shelf; nothing is drawn, no budget is read, `is_exploration` is
false on every row and the hourly line ends in `EXPLOIT ONLY`. That is
deliberate for the integration phase: the loop is being tested, not the
learner. Turning the draw on is the owner's change to this folder, not a
setting of yours.

## The episode id is yours

Every snapshot row carries `episode_id`, the name of the listing the row
belongs to, assigned by you before the row reaches this folder. The rule
for it is in the handover page (a row continues the shelf's previous
episode when last hour's row is exactly one hour earlier, did not close
the shelf, and the counter stepped as stock allows; otherwise it opens a
new one). Nothing here assigns an id. The command reads yours as given —
a new id on a shelf is an entry, the id it last priced on that shelf
continues the episode — and only *counts* the ids that disagree with the
rule (`episode_ids_disagreeing_with_the_rule` in the hour's report, with a
sample). A row without an id is not priced.

## Setting the host up

1. Linux, Python 3.11. `pip install -r requirements.lock`.
2. Wait for the owner's sync: `artifacts/` holds the five files,
   `features/` today's table, `config.yaml` the pruned config.
3. Dry-run one real hour with `--dry-run` and send the owner the
   snapshot, the response and the report.
4. Install the cron line.

## The cron line

```
# hourly, a few minutes past the hour, once the snapshot is written
5 * * * *  TZ=<the feed's zone> flock -n /opt/pricing/.hourly.lock \
  python3 /opt/pricing/price_hour.py --snapshot snapshots/$(date +\%Y-\%m-\%dT\%H).parquet \
    --features features/$(date +\%Y-\%m-\%d).parquet --workers 0 \
    --out decisions/$(date +\%Y-\%m-\%dT\%H).csv --report reports/hours/$(date +\%Y-\%m-\%dT\%H).json \
    >> /opt/pricing/logs/hourly.log 2>&1
```

`TZ` is the feed's own wall clock, so file names line up with the feed's
day. `flock -n` skips a run that would overlap the previous one; the event
store also locks itself on every write, so an overlap that slips through
is refused rather than double-priced.

## What you send back

The hour's report JSON and the console output under `logs/`; before the
first cron fires, one `--dry-run` hour's snapshot, response and report.
